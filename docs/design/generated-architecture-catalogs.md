# Generated architecture catalogs

| Field | Decision |
|---|---|
| Stable key | COH-E25-05 / CYB-185 |
| Requirements | NFR-019, NFR-026, NFR-027, EVAL-004, EVAL-029 |
| Contract | `contracts/architecture-catalog/v1` |
| Release evidence | `docs/architecture/catalogs` |

## Decision

COH publishes six deterministic architecture inventories: the resolved
capability graph, effective configuration, event producer/consumer routes,
durable model-surface events, Go module dependencies, and application
entrypoints. The generator consumes reviewed declarations plus every Go source
file under `cmd` and `internal`; it does not discover executable plugins or
accept runtime-provided catalog entries.

Every catalog uses one closed envelope and sorted record vocabulary. It records
the repository-relative path, declared version, and SHA-256 digest for each
source. The catalog digest is domain-separated and covers the canonical compact
form with an empty digest field. Pretty-printed checked-in evidence is then
verified against that digest and exact regenerated bytes.

## Conformance boundary

The existing Go architecture checker remains authoritative for package
allowlists, undeclared imports, unclassified packages, and broker/composition
authority boundaries. The catalog gate adds these release-blocking invariants:

1. capability definitions, providers, consumers, and edges form a closed,
   non-orphaned, acyclic graph;
2. the ten compiled control-plane authorities remain visible as static,
   non-replaceable, broker-intent-only records;
3. model-surface events are durable and have an explicit projection rule;
4. all active application entrypoints are rooted below `cmd`, while unexpected
   `package main` declarations elsewhere are denied (bounded `testdata` process
   fixtures are non-application test artifacts);
5. all Go sources are bound into dependency and entrypoint catalog provenance;
   symlinks, CGo, Go's dynamic `plugin` loader, and interpreter/plugin framework
   imports are denied; and
6. exact regeneration must match both a second independent run and the
   checked-in release evidence.

## Publication safety and recovery

Catalog attributes are structural identifiers, booleans, counts, revisions,
and digests. Secret-, credential-, token-, prompt-, content-, password-, and
private-path-bearing attribute names are forbidden. Absolute paths, source
content, environment values, model inputs, evidence payloads, callbacks, and
executable objects are never emitted. Each output is limited to 8 MiB and
131,072 records, and documentation links are checked offline.

Generation writes only to the explicitly selected output directory. CI uses
fresh temporary directories, so a denial, cancellation, or crash cannot update
checked-in evidence. Recovery is a clean rerun from the same immutable source
snapshot. Catalog updates are deliberate repository changes reviewed alongside
the source declaration that caused them.
